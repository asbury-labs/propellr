Purpose

Extend the completed foundation with three adjacent native form-control rules: input-button-name, input-image-alt and select-name. One approved implementation phase, then evidence review. Execution authorized by Tony's build request; current progress and executed evidence are recorded below.

Problem

The six existing implementations deliberately exclude these controls. A named native button does not prove an input button is named; decorative-image handling cannot be reused unchanged for an image submit control; selected option text is not a select label. The full catalog had 99 unimplemented rules at planning time. Broadening a generic nonempty-name helper would hide these semantic differences.

Solution

Reuse the bounded naming reader and reviewed label/ARIA checks, while retaining each canonical rule’s own selector, matcher and ANY/NONE combination. Author expectations from pinned source before differential runs. Target nine selected-partial implementations and 96 unimplemented rules, not nine fully ported rules or full catalog parity. Keep all 89 stable defaults intact, and preserve the exact memberships of existing three-rule and six-rule request helpers.

Planning basis and limits

Foundation PR #13 merged at 4b4f51e7 after 210 local/Ubuntu validation tests, one scoped repair push and source-backed dispositions for remaining review observations. That evidence validates the previous six-rule slice, not this proposed batch.

Read-only source inspection confirmed these three candidate rules are stable defaults in canonical 4.13.0. Their rule JSON, integration fixtures and submit/reset default-name check were inspected while preparing this plan. No proposed rule was implemented; no new fixtures, new-rule runtime tests, benchmark rerun or browser provisioning occurred. Existing foundation validation was rerun under pinned tools: all 210 tests passed. That baseline check does not validate the proposed rules.

Preserve explicit distinctions surfaced by prior review: rule-level impact; canonical integer-prefix tabindex parsing; composed implicit labels versus root-local references; native-query cost versus bounded JavaScript work; canonical relatedNodes versus richer potential trace evidence. Do not expand algorithms solely to satisfy a speculative bot suggestion.

Deferred: nested descendant-image IDREF support, generated names, embedded control-value naming, broader ARIA widgets, generalized multiple-label adjudication, layout/contrast expansion, closed roots, cross-origin injection, incremental optimization and the remaining catalog. Existing native-query work is not a constant-time or adversarial-page timing guarantee. These are candidates for later independently scoped plans, not hidden deliverables here.

The broader product target remains full agreed axe-core coverage. This plan prioritizes one adjacent batch rather than estimating the remaining catalog from rule counts. New source gaps or reference defects may require an explicit support decision before implementation proceeds.
