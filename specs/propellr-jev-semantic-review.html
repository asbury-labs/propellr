Purpose

Put Jev where it can add value in Propellr: judgments about meaning that deterministic accessibility rules cannot make, at a volume and price where model review is affordable, without ever touching verdicts, report counts or gate policy. The work follows the ranked recommendations in the ten-levels brief. It reuses the phase 2 infrastructure (bounded transport, approval gates, the LLM comparison arm, the labeling sheet) and applies what the attribution evaluation taught us.

Problem

The phase 2 evaluation sent Jev text-free structural fingerprints and asked a structural question: which ancestor is the component? That was the heuristic's own signal, so Jev, Haiku and structural-template/1 made the same choice on every dev case (decision precision 0.75 each). Meanwhile the naming rules (for example button-name, link-name, label and image-alt) only prove that a name exists. A button named "button", a link named "click here", alt text of IMG_2041.jpg, or ten identical "Remove" buttons all pass. Those judgments need text. Today it is deliberately dropped: naming evidence says "no name strings or control values retained".

Solution

First, add an opt-in, bounded, redacted text-capture contract (propellr-text-capture/1), separate from occurrence evidence. It records the text of the check that passed each naming rule, computed once during rule evaluation and shared with the capture. Then build a semantic naming review lane on top of it:

  • For every element that passes a naming rule, one fan-out request asks whether the name is descriptive in context, generic, or filename-like, and whether it can be distinguished from same-named controls.
  • Three arms get identical state: a deterministic heuristic, Jev and Haiku.
  • Each provider arm gets a frozen floor/bar confidence gate, chosen on dev only. Above the bar a case is flagged, between floor and bar it goes to review, and below the floor the arm abstains.
  • Two people adjudicate labels with the generalized labeling sheet, and a sealed holdout runs exactly once.

Results are SemanticReviewCandidate records that never enter Occurrence verdicts, Report counts or applyGate. Only if an arm is adopted does the review become an opt-in host capability. Only after that do the triage-at-scale and agent-loop guard tracks start, each with its own frozen protocol.

[] Phase 1: Text-capture contract (prerequisite)

An opt-in capture of the minimum text needed to judge a name, bounded like structure capture, redacted on the host before any egress, and kept out of occurrence evidence. Gate: Tony approves the protocol (fields, bounds, redaction, synthetic-only egress) before any code.

1. Write and freeze the protocol

  • [] Draft specs/semantic-text-capture-protocol.md.
    • Population: targets of all seven naming rules (button-name, link-name, label, image-alt, input-button-name, input-image-alt and select-name) with outcome pass.
    • Fields per target: the canonical name of the rule's own passing check (the text behind aria-label, aria-labelledby, implicit or explicit label, title, placeholder or content) and which check it was. It is computed once during rule evaluation under the same budget and shared with the capture, never recomputed by a separate helper. A pass without a text-bearing check (for example a presentational role) is name-unavailable. Also the role; the nearest preceding heading text; a short enclosing-container text excerpt; the same-name count on the page; for image-alt and input-image-alt, the alt string and image file basename.
    • Never captured: control values, password or hidden inputs, aria-hidden content, or anything in closed roots or inaccessible frames.
  • [] Bounds: 160 characters per string (the existing compact limit), 1 KiB per target, 64 KiB per scan, shared naming budget. Exhaustion makes the capture unavailable and never drops raw findings.
  • [] Redaction rules: email, phone, long digit runs, URL query strings and high-entropy tokens become typed placeholders such as [email]. Redaction that removes the text a question needs marks the target redacted-unavailable and is never guessed.
  • [] Egress policy: synthetic fixtures only, recorded as textDisclosure: "synthetic-only" in each approval record. No customer pages.

[] Phase 2: Semantic naming review pilot: corpus, arms and frozen protocol

Everything needed to evaluate, built and tested with no provider calls. The protocol is frozen, digest-pinned and approved before phase 3 spends anything.

1. Build the synthetic corpus

  • [] test/fixtures/semantic/corpus.ts: 12 original families × 20 cases. Splits are by family (4 dev, 8 sealed holdout). Cover descriptive names, generic names ("button", "click here", "more"), filename-like alt, duplicates that context can and cannot distinguish, misleading names, and non-English names.
  • [] No deliberately adversarial or injection cases: the terms review records adversarialTesting: "not-permitted".

2. Freeze the review protocol

  • [] specs/semantic-review-protocol.md, rubric semantic-naming@1. Questions for one target in one request:
    • descriptive in context: a score with situation-described levels;
    • generic: a noul;
    • filename-like alt: a noul, for image-alt and input-image-alt only;
    • distinguishable from same-named controls: a noul, only when the same-name count is 2 or more.
    Every question has an explicit exit (insufficient-evidence).
  • [] Defect probability, the one input to the gate. A noul has no separate confidence, and the questions point in different directions, so each answer is converted to the probability p that the name is defective:
    • generic and filename-like: p = noul;
    • distinguishable: p = 1 − noul;
    • descriptive, a score on L levels from "not descriptive" (0) to "fully descriptive" (L − 1): p = 1 − score / (L − 1);
    • the heuristic arm gives p = 1 or 0 where its rule applies and abstains otherwise; an exit answer abstains.
    Gates, dispositions and metrics are per question. Choice confidence is not used.
  • [] Floor/bar rule, fixed before selection:
    • Support: a threshold is eligible only if the set it defines holds at least 10 dev cases from at least 2 families. An empty or smaller set has no precision and never qualifies.
    • The bar is the smallest eligible grid threshold (0.50–0.95) at which dev flags (p ≥ bar) reach at least 98% precision.
    • The floor is the largest eligible grid threshold, below the bar when one exists, at which the review band reaches at least 50% precision. The band is floor ≤ p < bar, or p ≥ floor when there is no bar.
    • With no bar, the arm never flags. With a floor, answers at or above it go to review and the rest abstain. With neither, the arm abstains on every case.
    • Thresholds are pooled over at least 3 repeated dev runs, because Jev varied between identical requests.
  • [] Metrics: flag precision and recall, review-queue size, abstention, Brier, uncached latency p50/p95, cost per 1,000 targets, and run-to-run agreement. Adoption bar, fixed now: flag precision ≥ 98% at flag coverage ≥ 20% of true positives, and at least 10 points more recall than the heuristic at matched precision.
  • [] Pin the protocol digest (a tools/frozen-protocol.json-style pin for this protocol) and refuse evaluation otherwise.

Why this order

  • Text first. Every recommended use needs meaningful state. Without phase 1, a Jev evaluation repeats phase 2's result: the same signal as the heuristic, so no added value.
  • Naming review first among uses. Its population, the targets of existing naming rules, already exists. Its questions are narrow snap judgments (the ten-levels rules), and its output fits the recommended review-candidate lane without touching verdicts.
  • Scale and agent tracks later. They need either customer data (source files, real pages) or terms clarification, and they depend on the review lane's plumbing.

Capacity arithmetic (illustrative, not measured)

At about 300 input tokens per target, a million targets cost about $13 at $0.042 per million tokens. The published limits (1,200 requests a minute, 250,000 tokens a second, subject to change) bind first. Batching about 20 targets per page request gives about 50,000 requests, roughly 40 minutes per million targets. Batching conflicts with the "isolate the state" rule, so the pilot tests both per-target and per-page requests on dev before freezing one.

Risks

  • Nondeterminism. Jev's confidence moved 0.75 → 0.79 on identical requests in phase 2. Mitigations: pooled repeated dev runs, run-to-run agreement reported, and a margin disclosed next to every threshold.
  • Privacy. Name strings can carry personal data. Mitigations: redaction before egress, synthetic-only disclosure, capture off by default, and leak tests in validate.
  • Label cost. 240 cases × 2 people; the sheet's copy-to-identical feature reduces effort but is flagged in exports.
  • Scope creep. Error-message recovery (3.3.3) and consistent identification across pages (3.2.4) need captures beyond naming targets. They are deferred to a later protocol, not added to the pilot.

Rejected alternatives

  • Continuing to tune Jev for component attribution: it is a structural question that code answers for free.
  • Jev in the rule verdict path, gate waivers or scan skipping: this violates the separation of verdicts and gates in AGENTS.md.
  • Image judgments: Jev is text-only. A vision provider would be a separate evidence channel with its own costs.
  • Per-node or per-mutation calls: the rate limits cannot sustain them.
  • Distilling Jev's outputs into a local model: the MCA restricts it.
