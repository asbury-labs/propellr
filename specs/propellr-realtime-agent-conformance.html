Purpose

Make automatic change detection and one real agent/browser integration the next bounded implementation phase. Find lifecycle, transport and performance incompatibilities now, with nine selected-partial rules, rather than waiting for all 105. Reuse the same conformance suite for Browserbase and Browse CLI in separately approved follow-ups.

Full canonical coverage and materially better equivalent-work performance remain the product goals. This phase validates the execution model, not catalog completion or a nine-rule speed advantage.

Current gap

Today, clients explicitly request scans. Incremental requests fall back to full scans; observers only guard a scan's transfer window. Existing mutation/history tests prove rechecking, not an always-on observer or change-to-agent delivery latency.

The host assumes a Playwright Page, one active operation and a fixed fixture URL. Stagehand v4 has its own Page API. Remote reconnect semantics and CLI session identity are untested. Matching a URL is not proof of inspecting the agent's actual tab.

Chosen sequence

Phase Deliverable Boundary
1. Next bounded phase Automatic observation, reusable conformance harness, real Stagehand agent on local Chromium, early performance evidence. Stop for review. No further rules, true incremental cache or cloud provider required.
2. Browserbase Run the same scenarios on an authorized disposable remote session, including connection ownership, replay and latency. Separate cloud/account/network/spend approval. Chromium evidence only.
3. Browse CLI Drive the same scenarios through the CLI used by browse.sh skills; prove identity and stale element-reference handling. Separate approval; local mode first, no public-site skill execution.

Use narrow adapters at the host/test boundary. Keep browser analysis free of Node, Playwright, Stagehand, model SDKs and runtime schemas. Do not introduce a plugin platform, additional package graph, MCP server or provider-specific rule logic.

Implementation phases

All tasks unstarted. Approval of this plan is not permission to execute every phase: authorize phase 1 first and stop at each checkpoint. External model/cloud calls require the additional execution gates below.

[]1. Observation + Stagehand local

One implementation checkpoint containing the attach spike, automatic scans, real agent journey and measured responsiveness. Execute in this order; a failed attachment or unacceptable overhead blocks expansion rather than triggering a broad refactor.

1.1 Freeze the baseline and prove the attachment first

  • []Preserve the uncommitted native-form batch and all archives/worktrees. Agree the implementation base before creating the next branch: current HEAD alone does not contain those changes. No reset, silent cherry-pick, PR delivery or merge to manufacture a clean base.
  • []Pin proposed @browserbasehq/stagehand@4.1.0 as an integration/test dependency only, after reviewing tarball, transitive dependencies, licenses, native/extension requirements and install scripts. Existing Node 26.8.2, PNPM 12.4.1, Playwright 1.63.0 and Zod 4.6.2 stay unchanged; lifecycle scripts stay disabled. No global install or implicit browser download.
  • []First run a no-model connection spike: a disposable local Chromium, temporary profile, loopback-only debugging endpoint and a real HTTP fixture server. Stagehand and existing Playwright each hold their own connection to the same browser. Never cast a Stagehand Page into a Playwright Page. Verify page/document identity with a run nonce and cross-connection state assertions, not page-array position or URL alone.
  • []Verify full Chromium from the pinned project cache works with Stagehand’s required extension/debugging flags. Do not use a daily-driver Chrome profile or silently substitute a global browser. Test two-client coexistence, navigation, loss and independent disconnect. If same-page ownership cannot be proved, stop and propose the smallest boundary change before observation implementation.
  • []Write the execution protocol before runs: exact versions/artifacts, selected naming rules, observer signal scope, compatibility/version policy, fixture expectations, bounds, performance guardrails and failure dispositions. Review Stagehand’s Zod 4.4.x type constraint without downgrading project Zod or casting schemas; use its action primitives and JSON boundary, not cross-version extract schemas.

1.2 Add a bounded observation lifecycle, not a perpetual scan operation

  • []Add a schema-derived observe command returning a long-lived operation ID. Reuse inspect, subscribe, cancel and end for state, replay and cleanup. Keep manual scan and existing seven operations working. Decide and test additive capability/version handling before changing unions, wire validation, SDK/CLI or negative type examples.
  • []One observation per session, one in-flight evaluation and one coalesced dirty follow-up. An observation must not hold the existing active-operation lock forever. Manual scans/playbooks serialize with scan work; external agent mutations invalidate work rather than being presumed locked. Emit correlated scan-result events under the observation operation; retain bounded latest status plus existing raw history, not an unbounded child-operation list.
  • []Events carry session/observation ID, document generation, scan ID/epoch, dirty generation, reason categories and completeness. Separate observer status/freshness from static scan coverage: a past complete scan is not an evergreen clean page. Emit dirty/stale/paused/lost diagnostics even if the last committed result passed. New document generations never resolve old-document issues.
  • []Protect the live observation from operation eviction. Keep event/history retention and IPC byte caps explicit; test slow subscribers, dropped events and reconnect cursors without replaying browser actions. Stop/cancel/end waits for observer/timer cleanup, prevents later commits, and detaches without closing borrowed pages, contexts, connections or browser processes.
  • []Replace fixture-only borrowed admission with host-configured target registration and explicit allowed origins for this owned test application. Clients still cannot supply CDP URLs, grant origins or browser ownership. Recheck grants at navigation, collection and commit; deny redirects outside scope and do not expose credentials in session metadata. Managed dialog behavior remains unchanged.

1.3 Observe supported changes and schedule truthful full scans

  • []Install signal collection before the initial scan, capturing a dirty generation so mutations during installation/collection/transfer cannot disappear. Observe DOM child/attribute/text changes, accessible open-root/slot changes, same-origin frame lifecycle, resize/scroll, relevant input/change/focus events, stylesheet resource load and font readiness. Record bounded invalidation metadata, not arbitrary DOM text, input values or event payloads.
  • []Coalesce signals with proposed 75 ms quiet delay and 500 ms maximum wait; use bounded scheduled work, never a continuously repainting or requestAnimationFrame polling loop. At sustained churn attempt bounded progress, then emit an explicit unstable/overrun state; do not fabricate an atomic snapshot. A scan invalidated before commit cannot enter report history. Drain newer dirtiness after any valid commit.
  • []Keep evaluation actual: full. No reusable incremental facts, dependency graph or new native-query index in this batch. A requested incremental mode still reports its full-scan fallback. Preserve reader, naming, occurrence, evidence and diagnostic bounds, and expose saturation instead of dropping it silently.
  • []Document signal limits up front: CSSOM-only edits, continuous animation, property-only changes without events, attachShadow on an existing host, closed roots and denied frames are not magically observable. For each, implement and test a bounded supported trigger/reconciliation path or declare observation coverage unavailable for that branch. Do not turn a manual refresh into proof of automatic detection. Known unsupported CSSOM/animation watch scope cannot advertise comprehensive live freshness.
  • []Rebind authorized observation on full/same-document navigation, back/forward restoration and frame replacement without leaking observers or reusing stale document IDs. Background-page throttling/suspension must be visible and force reconciliation on resume. Synchronous browser evaluation is not forcibly interruptible on a borrowed page: measure overruns and report limits; never kill an agent’s browser to satisfy a timeout.

1.4 Build one reusable conformance suite

  • []Create one owned HTTP application with deterministic clean/broken/repaired/recurring states: native naming defects, DOM replacement, external label updates, dialogs, async content, styles/classes, open shadow/slots and same-origin/denied frames. No new product playbook or public-site automation. Expected defects are authored before engine comparisons; every state is held until the test barrier, with the guarantee limited to observable settled states, not every transient frame.
  • []Provider adapter responsibility: start/attach, identify current page, execute an action, resolve a scoped target, disconnect/reconnect and release owned resources. Shared suite owns journeys, expected states, stale/partial semantics and reporting assertions. Do not fork expected results per provider. Maintain an explicit capability matrix; unsupported mandatory capabilities block that provider’s support claim.
  • []For each settled mutation, await an automatically emitted result with no manual scan call or fixture-specific invalidation shortcut. Replay the same state into separate equivalent fresh-full Propellr and integrity-checked canonical contexts. Compare rule state, raw occurrences, scoped target, impact and check evidence before grouping. Retain existing IMP-001/002 dispositions separately, not in an expanded allowlist.
  • []Test mutation during scan/transfer/commit, last-update-wins ordering, queue saturation, lost page, cancellation, subscription gaps and cross-navigation identity. Verify introduced/persistent/resolved/recurring findings and that narrower, stale or partial scans cannot resolve history. Include an idle watch with no repeatedly scheduled full scans.
  • []Run core observation across Chromium, Firefox and WebKit using existing Playwright support. Stagehand lane is Chromium-only; never present its results as three-engine adapter coverage. Complete naming/history scenarios use explicit supported rules; separate nine-rule/default requests retain target-size/unimplemented-rule gaps and indeterminate gates.

1.5 Prove real agent usefulness, not only SDK connectivity

  • []Add a small opt-in tool-use harness: Stagehand supplies browser actions; schema-derived Propellr commands/results supply accessibility tools. Stagehand v4 exposes act/observe/extract primitives, not an assumed legacy agent() API. Use one explicitly approved model/client and a bounded tool loop, not a new general agent framework. Typed findings must reach the model, not merely an assertion hidden beside a scripted browser driver.
  • []Freeze model/version, prompt, available tools, token limits, deadline and maximum 12 tool steps per journey. Proposed evaluation set: three journeys (new/repair, partial-or-stale, reconnect/target-replacement), three independently initialized trials each. Obtain explicit model/provider/data/spend approval and a numeric cost cap before any charged call. No credentials means blocked live validation, never a mock-only success or silently skipped support gate.
  • []The agent navigates/opens a fixture state, starts observation, consumes findings, identifies the actual scoped target, invokes a permitted test-fixture repair and verifies the subsequent result. Do not hand it the oracle’s defect list, expected verdict or hidden repair answer. Use task prompts and ordinary fixture UI, with an independent runner checking real state. No agent-authored arbitrary JavaScript repair outside the owned fixture permissions.
  • []Score semantic correctness separately from navigation/model reliability: expected issues found, exact targets inspected, verified resolution, tool errors, latency, tokens/cost and human intervention. Require zero false clean, false resolution or unauthorized actions; report every attempt and block on failed mandatory journeys. No rerun-until-green, cached action substituted for live inference, or treating LLM navigation failure as engine success.
  • []Test page-text prompt injection and malformed/stale tool inputs against deterministic host grants. Model/browser/provider secrets remain outside page evaluation. Send only synthetic fixture data to approved providers; raw DOM/screenshot/recording capture is opt-in and sanitized. Page content cannot authorize tools, change rule selection or suppress coverage gaps.

1.6 Measure before scaling rule coverage

  • []Freeze a local performance protocol before collection: 200- and 1,000-element fixtures with the same explicit supported naming selection in both engines; two warm-up sequences, 30 measured held revisions per size/engine, one 200-mutation burst, a 60-second idle interval and a 10-minute Chromium soak after retention warm-up. Keep all samples, failures and exclusions. This is engineering evidence, not high-confidence percentile certification.
  • []Compare no-observer baseline, Propellr automatic full-scan observation and a reference full scan triggered by the identical test-harness change signal. Give both equal browser reuse and page states. Separate correctness replay from timed runs to avoid canonical scans or extra parallel browsers distorting Propellr delivery time. Alternate engine order and record host load.
  • []Measure mutation-to-invalidation, queue delay, scan/transfer, report commit and client delivery using correlated timestamps in each clock domain; do not subtract unsynchronized remote clocks. Report end-to-end p50/p95, throughput, event-loop delay, host CPU/RSS/heap and retained resource counts. Browser CPU/memory unavailable under a comparable collector is null with a reason, not zero.
  • []Proposed local responsiveness gate, reviewed in the protocol before measured runs: p95 mutation-to-usable-client-result at most 500 ms for the 200-element supported fixture, zero missed held revisions, no overlapping evaluations and zero idle repeated full scans. Report the 1,000-element/burst/soak results and investigate stalls or unbounded growth before accepting the architecture. Do not silently relax a failed target or invent a speedup from reduced coverage.
  • []Agent/model latency and provider RTT are separate lanes from engine latency. Record tool result bytes and time to actionable findings, including subscription delivery. Keep original bench:slice workload intact; run it once only if shared scan code changed. Watch-only costs belong in the new benchmark, not a nine-rule headline ratio.

1.7 Testing strategy and acceptance

  • []pnpm validate under unchanged pins: existing suites plus real no-key observation and local deterministic integration suites wired into CI when implemented. No placeholder script and no existing fixture expectation weakened.
  • []Planned pnpm test:observation: scheduler/races, automatic three-engine results, freshness, history, budgets and cleanup. Planned PROPELLR_INTEGRATION=stagehand-local pnpm test:integration: real SDK/session identity and common conformance, no model calls.
  • []Planned PROPELLR_INTEGRATION=stagehand-local pnpm test:agent: required opt-in real-model journeys after approval. Fail clearly on missing credentials/configuration when invoked; local default validation must not spend money. Planned pnpm bench:observation: the frozen no-model responsiveness/idle/soak protocol.
  • []Retain source/bundle/fixture/provider/model pins, commands, exact outcomes, conformance capability matrix, resource cleanup and raw timing samples in a fresh archive. Update README, provenance and improvements ledger only with verified benefits. A green no-key CI run alone does not establish agent compatibility.
Stop boundary: review working observation, actual Stagehand/model evidence and performance together. Missing live approval, failed compatibility or unresolved performance/correctness findings leave phase 1 incomplete. No automatic provider rollout or new rules.

[]2. Reuse on Browserbase

Separately approved follow-up, not part of phase 1’s completion claim. Browserbase is the browser infrastructure lane; reuse the same agent/scenario definitions rather than invent another accessibility runner.

2.1 Remote lifecycle and conformance

  • []After explicit cloud/test-account, origin, model, recording/retention and numeric spend approval, pin the Browserbase client, returned browser build and region. Create only disposable authorized sessions. No publishing Functions, customer sites/data or permanent deployment. Use a dedicated ephemeral fixture endpoint or reviewed in-session network interception; do not assume remote Chrome can reach localhost or expose a workstation tunnel by default.
  • []Reuse the same page identity handshake, fixtures, raw comparison oracle, event/freshness/history assertions and agent journeys.   • []Explicitly request and verify supported keep-alive semantics before testing connection loss. Default disconnect can end a Browserbase session; reconnect guarantees depend on plan/capabilities. Test agent-connection loss separately from Propellr-client loss, two connections, remote timeout, navigation and denied frames. Provider expiration becomes lost/unknown, not recovered success.
  • []Propellr detach must not release the agent’s cloud session. The test owner explicitly releases created keep-alive sessions in final cleanup and verifies release even after failures.
